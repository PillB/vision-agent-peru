The total intended structure is:

* 4 macrocycles;
* 9 roles per macrocycle;
* 5 passes per applicable role;
* 3 challenge rounds per macrocycle.

A role may be marked inapplicable only with:

* a written applicability assessment;

## 7. Red–Green–Refactor discipline

### Red

Before fixing a new defect:

* write the smallest behavioural, statistical, security or provenance test that demonstrates it;
* run the test;
* capture failure evidence;
* prove it fails for the intended reason;
* specify acceptance criteria; and
* register the test in Graph Memory.

### Green

* implement the smallest coherent correction;
* avoid unrelated redesign;
* preserve useful existing behaviour;
* run the targeted test;
* capture passing evidence; and
* record the decision.

### Refactor

* improve maintainability, reuse, observability or efficiency;
* do not change behaviour without returning to Red;
* rerun affected tests; and
* record any new process-improvement proposal.

For statistical or methodological defects, Red means a falsifying fixture, simulation, counterexample, independent calculation or acceptance threshold—not merely a conventional unit test.

* probe system-level consequences.

* perform an isolated or blind reproduction;
* automate stable checks in CI or monitoring;
* document residual limitations;
* pass or fail the role gate.

### Mandatory reporting-integrity tests

1. **Static display scan**

   * locate numeric literals and formatted values in report and dashboard code;
   * classify each as reportable, legitimate constant, fixture or suspicious;
   * do not treat the scan alone as proof.

2. **Clean recomputation**

   * delete generated reports and eligible caches;
   * rerun from raw or approved source data;
   * reproduce every figure.

3. **Source mutation test**

   * change a controlled source row, model output or fixture;
   * predict which figures should change;
   * verify they change by the expected amount;
   * verify unrelated figures remain stable.

4. **Model mutation test**

   * replace or perturb a test checkpoint;
   * verify model-derived figures change;
   * verify the model version and run ID propagate to the report.

5. **Stale-cache test**

   * update source data or model results;
   * verify stale report data cannot survive unnoticed;
   * verify freshness metadata and invalidation.

6. **Missing-lineage fail-closed test**

   * remove required provenance;
   * verify production report generation fails or visibly marks the value unverified.

7. **Independent re-derivation**

   * recreate critical metrics through a separate implementation, query or notebook;
   * compare within a predefined tolerance.

8. **Table-chart-summary consistency**

   * verify the same metric agrees across machine-readable output, API, table, chart, narrative and PDF.

9. **Snapshot-versus-live labelling**

   * clearly label intentionally frozen historical snapshots;
   * retain source run IDs and hashes.

10. **Report build reproducibility**

    * regenerate reports from an isolated checkout and environment.

No final statement may claim that all figures are dynamic unless all reportable figures pass these tests.
